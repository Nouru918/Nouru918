## 3. 게임 QA 포트폴리오
<details>
<summary><b>공통 QA 방법론(클릭하여 펼치기)</b></summary>
본 문서에 서술된 QA 프로세스는 전체 프로세스는 전체 프로젝트에 적용되는 공통 표준 가이드라인입니다.<br>
게임의 장르, 플랫폼, 라이브 빌드의 특성에 따라 검증 기법은 달라질 수 있습니다.
<p>&nbsp;</p>

<p>인하우스 개발 권한이 없는 외부 라이브 빌드 환경의 제약을 극복하기 위해 JIRA에 연계하여 독자적인 4단계 외부 QA 프로세스를 다음과 같이 수립하였습니다.</p>

| 단계 | 세부 내용 |
| :--- | :--- |
| **1단계**<br>결함 발견 및 등록 | QA 진행 중 발견된 원인불명 이슈의 등록 |
| **2단계**<br>구조화 및 분석 | 발견된 이슈를 재현 및 교차 검증하여 원인을 규명하고, 개선이 필요한 사항을 기록 |
| **3단계**<br>라이브 패치 모니터링 | 패치 이후 미완료된 이슈의 개선 여부 검증 및 잔여 이슈 추적 |
| **4단계**<br>완료 및 저장 | 패치 이후 온전히 해결된 티켓을 자산화하여 관리 |
 
<br>

<p>QA 검증 영억은 다음과 같습니다.</p>

| 검증 영역 | 검증 대상 |
| :--- | :--- |
| **기능** | 기능 및 시스템의 정상 동작, 조건별 동작, 예외 케이스 |
| **레벨 디자인** | 스테이지 구성, 동선, 배치, 진행 구조 및 플레이 경험 |
| **밸런스** | 난이도, 전투 효율, 보상, 성장 및 콘텐츠 간 밸런스 |
| **성능 및 최적화** | 프레임, 로딩, 메모리, 끊김 등 플레이 성능 |
| **UI/UX** | 화면 구성, 인터랙션, 가독성, 피드백 및 사용성 |

<br>

<p>QA 이슈의 영향도에 따라 다음과 같이 심각도가 분류됩니다.</p>

| 심각도 | 의미 |
| :--- | :--- |
| **Highest (매우 높음)** | 서비스 플레이 진행이 불가능하거나 핵심 기능에 심각한 영향을 주는 수준 |
| **High (높음)** | 주요 기능 또는 플레이 경험에 큰 영향을 주는 수준 |
| **Medium (보통)** | 기능 이용은 가능하지만 명확한 영향이 있는 수준 |
| **Low (낮음)** | 영향도가 낮아 우선순위가 상대적으로 낮은 수준 |
| **Lowest (매우 낮음)** | 심각도가 매우 낮아 우선순위가 가장 낮으며, 후속 조치가 필요하더라도 긴급성이 거의 없는 수준 |

</details>
